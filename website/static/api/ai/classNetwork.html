Detailed Description

Manages the TCP connection to the Zappy server.

Owns the socket and two buffers: an inbound queue of messages received from the server and an outbound queue of messages waiting to be sent. Polling, receiving and flushing are driven externally (see pollCheck and processSendQueue).

◆ pollCheck()

void Network::pollCheck ( bool  block = false)

Polls the socket once and pumps both queues.

Waits for readiness (blocking when block is true). When the socket is writable and there are queued outbound messages, flushes them via processSendQueue. When data is available, appends the received message to the inbound queue. Outbound interest is only registered while _sendQueue is non-empty, so a blocking call with nothing to send waits on input rather than spinning.

Exceptions
ZappyExceptionwith POLL_ERROR on poll failure or CONNECTION_LOST if the peer hangs up or errors.

◆ setServerMessageHandler()

void Network::setServerMessageHandler ( std::function< bool(const std::string &)>  handler)

Registers a handler for server-initiated lines.

The handler is invoked for every complete inbound line. If it returns true the line is considered handled (e.g. a broadcast or dead notification) and is kept out of the command-response queue; if it returns false the line is queued as a normal command response. Running at the line boundary means asynchronous messages are handled even while a synchronous command is blocked in waitResponse.

Parameters
handlerThe predicate to consult for each inbound line.

◆ waitResponse()

std::string Network::waitResponse ( )

Blocks until a command response is available, then consumes it.

Repeatedly polls the socket in blocking mode until _messageQueue is non-empty, then removes and returns the oldest queued response. Consuming the response keeps every command aligned with its own reply: back-to-back commands (e.g. Look then Inventory) no longer read each other's response.

Returns
The oldest command response line, including its trailing newline.
Exceptions
ZappyExceptionwith POLL_ERROR or CONNECTION_LOST, propagated from pollCheck.
